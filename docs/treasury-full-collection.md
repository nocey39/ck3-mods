# 国库全额公共征税 0.7.6

## 生效边界

统一政策按原生国库能力识别，不维护行政、天朝、共和国等政体名称名单。

全额征税须同时满足：地方符合现有有地伯爵及以上接收资格；自身和每一级上级均支持原生国库；最高领主是启用本模组统筹的独立财政中央；中央和地方的当前头衔、财政归属、拨款状态均已初始化；当前直属封臣关系与契约一致；统一征税义务已经安装。

最高领主不是国库政体、中间有非国库上级、游戏规则关闭统筹、或尚未完成接入时，原有税额表达式原样恢复，统一义务为零。不要求中央预算为正；预算锁和重算锁不会临时关闭税制。非国库封臣及朝贡关系沿用原版。

断链后同步移除模组的原生返款阻断，避免退出全额征税后仍禁止原生返款。政体/封臣关系变化检查受影响子树；月度检查已登记地方；季度重建沿用现有机制。不新增每日世界扫描。

俸禄、庄园、住所和其他个人收入定义保持原样。这里调整的是引擎公共税收契约，不把角色的全部月收入或现有金币余额清空。

## 生成方式与兼容

CK3 没有按财政能力动态追加任意政体契约组的接口。为覆盖自定义契约，构建工具按游戏文件及 `dlc_load.json` 中实际启用顺序合并契约数据库，再为每个非朝贡契约组加入同一个隐藏公共征税义务。旧义务的 `tax`、`min_tax`、`tax_factor` 只在统筹真正生效时归零；新义务只添加一次 100% 税率及最低税率。未生效时执行旧表达式，避免多税务义务叠加收取数倍。

构建会保留非税字段、朝贡组和辅助文件，并处理 `replace_path`、同路径覆盖、同名定义和文件局部变量。遇到不支持的结构会报错，不猜测税率。`manifest.json` 记录来源哈希、覆盖结果、修改字段和输出哈希，不记录本机绝对路径。

仓库附带 CK3 1.21.0.3 纯原版生成基线。**启用其他模组时应按当前组合重新构建，且国库统筹放在所有其他模组之后加载。** 该层使用 `replace_path="common/subject_contracts"`；未重建就改变游戏版本、启用列表、模组内容或顺序，可能覆盖第三方的新定义。生成工具是加载前适配，不能宣称自动兼容未来所有模组。

```powershell
node tools/build-treasury.js --game 'D:/steam/steamapps/common/Crusader Kings III/game' --user-dir "$env:USERPROFILE/Documents/Paradox Interactive/Crusader Kings III" --output work/treasury-build-076
```

输出须为新目录，工具不会修改已安装模组、启用列表、游戏或存档。按输出中的 INSTALL.txt 安装；不要同时启用工坊版和本地版。目录移动后更新本地 `.mod` 的 `path`。

政策版本 16 用于旧档登记与义务初始化，并保留已保存的预算政策。完整替换模组后重启游戏再读档。

## 验证与实际边界

源码验证、财政表达式回归、未知契约生成回归和实际财政链触发器回归分别运行。生成回归包括同组多个税项、无税组、零税组、动态与 -100% 系数、共享朝贡契约、非税字段保留及文件覆盖顺序。

这些回归不代替 CK3 引擎实测。最终税率修正顺序、引擎可征税收入的具体渠道、存档迁移和多层级月结仍须在游戏中核验。重点场景：原版行政边疆、未知国库政体、非国库最高领主、国库链中途断开、政体切换和继承。观察税收与发展/军事拨款，同时确认俸禄与庄园收入仍保留。
