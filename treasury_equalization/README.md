# 国库统筹财政 0.7.6

适配 CK3 1.21.0.3。以创意工坊 0.7.4 为修复基线。

## 0.7.6

- 全额公共征税按国库能力和完整财政链判断，移除五个原生政体契约的名单限制。统一隐藏义务只收一次 100% 公共税款，统筹生效时中和原契约的税率与增减系数；未生效时保留原表达式。个人俸禄、庄园和住所等收入定义保持原样。
- 最高领主非国库、中间出现非国库领主、尚未登记或财政归属过期时，保留原生税制和返款。新地方先安装义务并完成登记，再进入全额征税；中央缺钱不会导致税制反复切换。
- 政策版本 16 重建地方状态，补上完整上级链校验、断链子树清理、中央标记修复与原生返款恢复。保留现有预算设置。
- 本版包含按原版生成的契约数据库。**使用其他模组时必须先按当前组合构建，并将国库统筹置于最后加载。** 游戏、模组或顺序改变后重新构建，避免旧数据库覆盖其他模组的新契约。

```powershell
node tools/build-treasury.js --game 'D:/steam/steamapps/common/Crusader Kings III/game' --user-dir "$env:USERPROFILE/Documents/Paradox Interactive/Crusader Kings III" --output work/treasury-build-076
```

输出使用新目录，不修改游戏、存档、启用列表或已安装模组。详细边界和游戏内核验场景见仓库 `docs/treasury-full-collection.md`。

## 0.7.5

- 发展与军事按设定份额支付。一项没有接收人或份额为零时，未拨资金留在中央国库。
- 发展、军事和枢机基准均由通道目标金额除以原生有效接收单位计算，计入原生部会、契约等权重。
- 禁止中央将自己的头衔登记为地方。政策版本 15 会在首次重算时清理旧记录并重建地方名单，沿用主要头衔上的手动政策。

## 0.7.4

- 预算总额直接读取原生实时可用预算 `character_treasury_new_budget_capacity`。不再用月结余加旧的计划拨款倒算，避免原生重算、接收人变化或安全限额使旧账与当前支出错配。
- 原生 AI 年度预算保护改挂 `random_yearly_playable_pulse`，与本版本原生备用预算执行的位置一致。
- 所有合格中央每月维护预算与工资曲线，取消 AI 结余必须小于 -5 或大于 25 才重算的门槛。
- 新合格封臣在头衔、封臣关系等事件中立即登记到同一地方名单并接入拨款，不再先纳税、等待季度再领取发展预算。旧版仅纳税而未入列的状态在迁移与维护时清理。
- 中央退出统筹时清理其地方状态；头衔由合格继承人接手时保留该头衔的设置与地方名单。
- 富裕的文官地方保留少量基础发展权重，取消储备约达目标 185% 时突然归零的断点。最低需求系数为 0.15，叠加最多 50% 的财富扣减后，模组新增的有效权重至少为基础需求的 7.5%。这是一项分配权重下限，不是保证每位封臣领取固定金额。
- 发展基准安全上限按原生实际接收单位计算，包含部会、契约和其他修正，不再用地方权重总和加固定 0.25 猜测。已执行金额按各通道实际单位乘最终基准记录，供诊断使用。
- 政策版本提升至 14，旧存档首次接入时重建地方权重；保留随主要头衔保存的手动政策。

## 财政分配规则

财政领主的原生可分流收入默认 5% 进入私人金币、95% 进入国库。私库比例可在预算窗口调整，范围 0% 至 100%。庄园、俸禄等其他收入渠道沿用原版。

引擎扣除非预算经常支出后提供当前可用预算 C；模组将负值按零处理。中央留存比例 r 默认 5%，每月可分配总额为：

`E = max(C, 0) × (1 − r)`

留存比例作用于扣除经常支出后的可用资金，不是全部入库收入。不从已有国库存款额外拨款；若经常支出已经耗尽全部可用资金，预算为零。

俸禄先从 E 支付。有效原生官职、品级和修正形成单位数 N，自动待遇目标为 `0.5 + 1.5 × E / (E + 20N)`；无有效官职时目标为 0.5、支付为零。初次采用目标，之后每个实际月份向目标靠近 25%；同月重复打开窗口或执行预算不会加速变化。玩家可微调待遇至 0% 至 200%，总俸禄仍不超过 E 的 10%。

扣除俸禄后，先保留原生枢机预算份额，其余资金作为发展与军事共同池。两项手动份额合计 100%。达不到支付条件的份额留在中央国库。军事预算仍按原生军事职责和契约确定接收人，个人俸禄另行计算。

发展基础需求为 `min(20, 1 + 直辖郡数 / 5)`。地方储备目标为 `min(10000, 300 + 180 × 直辖郡数)`，再乘时代系数、军事地方系数 1.5 和储备游戏规则系数，最低 200。时代系数依次为 0.8、1、1.25、1.5；紧凑、标准、宽裕规则系数分别为 0.65、1、1.5。

文官地方的需求系数为 `clamp(2 − 国库 / 储备目标, 0.15, 2)`；财富额外扣减最多 50%。地方越富裕，新增发展权重越小，仍保留少量基础权重。原生契约和部会自身的权重继续由引擎处理。地方储备需求按季度更新；继承、资格或军事职责变化时及时重算。

所有箭头左键调整 1 个百分点、右键调整 5 个百分点，免费即时生效。“执行预算政令”另保留原生政治成本和效果。

## 资格与兼容

中央须为拥有原生国库、使用原生国库法律的有地独立统治者，且符合生效范围和政体游戏规则。AI 还须有合格的伯爵及以上国库封臣。独立要求用于原生预算读取接口；模组没有为所有附庸单独建立中央预算。

地方须为有地、伯爵及以上、拥有原生国库和预算法律接口的封臣，且每一级上级都在同一国库体系中。各级合格地方直接参与最高财政领主分配。男爵市长、无地角色以及财政链中存在非国库上级的地方不接入。

公共统收通过构建生成的统一义务，对已接入完整拨款体系的地方实行 100% 公共税率。非国库封臣、未接入地方和朝贡关系保留原生税率。开局规则支持全图、玩家与主要大国、仅玩家，以及政体范围和储备规模选项。

覆盖范围包括原生预算 scripted effect、5 个事件、完整契约数据库、1 个发展法案组和预算窗口 GUI。契约通过工具合并，其他同名定义或窗口仍需兼容。事件优先级为 10。年度维护采用追加挂钩，不覆盖 `yearly_on_actions.txt`。

适配器可覆盖角色触发器 `teq_adapter_excludes_government` 和 `teq_adapter_military_region`，分别排除政体、标记军事地方。完全自有货币或自行结算的财政系统不自动兼容。

先按当前模组组合构建，备份存档与旧版模组，完整替换目录并重启游戏。政策版本 16 重建旧地方缓存，并沿用已保存的私库比例、中央留存比例、发展份额和工资微调。原先设为 0% 的份额继续按 0% 支付。

仓库根目录运行：

```powershell
node tools/validate-treasury.js --game 'D:/steam/steamapps/common/Crusader Kings III/game'
node tools/test-treasury-finance.js
node tools/test-universal-tax.cjs
node tools/test-treasury-chain.cjs
```

静态验证检查脚本结构、引用、本地化和实际原生年度挂钩。财务回归直接读取并执行本模组的相关源码表达式，覆盖重复校准、收支扰动、留存边界、富裕地方基础需求、原生额外接收人和工资月度变化；它不是 CK3 引擎模拟器。

审查时只读核对了本机原版脚本、引擎导出接口、当前 17 个启用模组及四份现有存档快照。快照中的天朝发展与军事基准均非零，无法据此还原所有间歇断款。当前模组组合未发现同名预算覆写冲突。修复后旧档的实际月度收支、长局性能和多人联机仍需游戏内验证；不要把源码回归通过理解为已完成这些实测。
