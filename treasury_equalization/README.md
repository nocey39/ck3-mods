# 国库统筹财政 0.6.7

适配 CK3 1.21.0.3（Florin）。符合资格的玩家和 AI 默认采用同一规则，无需决议或每月手动操作。

## 财政规则

中央按月统筹现金流，再将预算持续拨给地方。各级合格地方直接参与中央分配，中间封臣无需垫付下级预算。结算使用原生国库收入与支出，不靠一次性事件补助，也不直接分走已有国库存款。

每月预算总额 E 根据上期总额、国库月收入 I、净结余 B 和留存比例 r 调整：

`E = clamp(上期 E + B − r × I, 0, (1−r) × I)`

宫廷、兵士等其他支出已体现在 B 中。国库未分配比例是月入库收入的留存目标，默认 **5%**，玩家可在预算面板按 **左键1、右键5个百分点**调整，范围 **0%–100%**。设置保存在主要头衔上，继位及读档保留。收入变化与引擎缓存可能使收支经过一至两个月才接近目标。

财政领主的原生可分流收入（直辖税、封臣税、贡金）默认 **5%进入私库、95%进入国库**，玩家和AI相同。玩家可在同一预算面板调整“私库收入比例”，左键每次1个百分点、右键5个百分点，范围0%–100%，也可一键恢复5%。免费即时生效，调整后重算可用预算，不动国库存款。该设置随主要头衔保存；AI不自行调整。庄园、工资等其他收入渠道继续沿用原版。它与入库之后的“国库未分配比例”是两个不同设置。

## 俸禄与公共预算

俸禄作为先支付的行政成本，按原生官职、品级及其修正形成的有效权重总数 N 计算，不再参与发展、军事预算的比例竞争。

- 国家目标工资系数 `F = 0.5 + 1.5 × E / (E + 20N)`。E 是扣俸禄前的当月可用总预算，N 是原生官职、品级及修正形成的有效权重。每单位官职的财政能力越强，系数越高；增长逐渐放缓，范围为0.5至渐近2。无有效官职时目标为0.5、实际支付为零。
- 初次计算采用目标系数；此后每月向新目标靠近25%，同月重复打开界面、调整预算或AI执行法案不会加速变化。实际支付 `P = min(N × 当前系数, E × 10%)`；财政不足时立即折发，收入恢复后仍受同一上限约束。
- 预算面板俸禄行显示可调待遇百分比，100%代表原生官职工资基准1倍。待遇等于自动系数加玩家微调，范围0%–200%；左键调1个百分点，右键调5个百分点，点击待遇数值恢复自动。手动调整不推进自动系数的月度变化，AI不会自行改变微调。实际折发后的工资见“基础值”，总工资仍不超过总预算10%。

扣除 P 后，发展与军事使用共同预算池，份额合计100%。例如60%/40%，左键减少发展后为59%/41%，右键减少后为55%/45%；另一边只转移实际可用百分点，在0%/100%边界不会越界。首次按原生相对权重取整初始化，玩家调整后随主要头衔保存。若原生还有枢机预算，其权重另行保留，发展、军事百分比只描述两者共同池。没有实际受益方时，该通道不能凭空付款；金额与基础值显示当前原生实付。

地方需求按直辖郡数与国库储备计算。基本权重为 `min(20, 1+郡数/5)`；储备目标依规模为 1500 / 3000 / 5000 / 8000 / 12000，缺口系数为 `clamp(2−国库/目标, 0, 2)`。地方越富裕，发展拨款越少；低于零国库后不再无限加权。**军事地方不领取发展预算，只保留军事预算**，其储备目标乘 1.5；个人职位俸禄另按上述工资规则支付。

所有比例与待遇箭头即时生效，免费，不需要再按执行。预算窗口保留独立的“执行预算政令”按钮，仍消耗原生执行成本并触发原生政治效果；此按钮不是比例调整的确认按钮。自动校准不消耗政治资源，也不重复发放原生好感奖励。

## 接入与兼容

拥有原生国库、可独立结算原生预算的统治者自动统筹辖下合格地方，适用于共和制、行政制、教权制以及使用相同接口的第三方政体。共和制议会采用统一的留存、俸禄与公共预算规则，定期预算维护不再弹出原版俸禄档位选择。引擎将统筹所需的预算读取接口限制在独立统治者。附庸的原生教权预算保留原有结算，普通附庸继续按地方资格接入。缺失的发展预算入口会补齐，缺省发展权重为 30，已有合法自定义发展法案及当前选择保留。

接入后仍采用统一公共征税，不保留对方原有封臣税率；中央的原生可分流税收统一采用私库比例设置，默认95%入国库、5%私人金币，包括原版行政制与使用相同接口的自制政体。分流不是封臣缴税率。原生使用同一个分流通道处理直辖税、封臣税与贡金，因此此控件不能只改直辖收入。混合政体沿用既有征税边界，没有逐契约重构税制；统一征税修正可能影响接入领主辖下的非预算封臣。其他非财政机制不在修改范围内。

实际覆盖范围：

- 选择性覆盖 **12 个原生 scripted effect 和 3 个事件定义**，在 **24 个预算执行调用**前释放旧工资占比修正，执行后加入同 scope 校准；事件使用 `id_override_priority = 10`。保留原政治成本与非接入国家行为。
- `common/on_action/yearly_on_actions.txt` 以 1.21.0.3 原版为基准，接入原生年度预算重算，并跳过已纳入统筹的议会俸禄档位事件。修改同文件的模组需要合并。
- 完整覆盖 `gui/window_treasury_budget_change.gui`，修改同一预算窗口的 UI 模组需要合并。
- 独立文件覆盖 `budget_allocation_ministry_law` **一个法案组定义**，补齐统筹所需的发展预算入口。对具备原生军事预算接口但没有可用军费法案的财政主体，填入一条只提供初始权重的统筹军事法案。原生拨款对象决定实际支付。发展和军事法案使用独立键。另替换三项发展预算名称本地化。

其他模组若覆盖上述定义、使用更高或相同事件覆盖优先级、另行改写预算基准、重复发放相同资金，需合并或适配。第三方直接新增的原生预算执行路径也需补上后置校准；完全专有货币或自行结算的财政不会自动接入。

适配器可覆写角色作用域触发器 `teq_adapter_excludes_government` 或 `teq_adapter_military_region`，分别用于退出统筹和标明军事地方。默认均为否。沿用旧自定义旗标的适配器可在旗标定义所在的模组中通过这两个触发器接入。原版军事契约旗标继续自动识别。

## 性能、存档与验证

每月更新合格财政主体及其地方缓存；季度刷新地方需求，国家工资系数使用已有预算与官职权重按月更新。不新增每日世界人物扫描、逐建筑统计或逐笔支付事件。原生 AI 执行预算时增加受资格与防重入保护的准备和校准。打开预算窗口也会校准一次；常规校准包含测量及最终执行两次原生重算，零俸禄法案采样时增加临时探测。

收入分流每个财政领主每月最多重新校准一次；同月重复打开窗口或执行AI预算不重复探测，玩家修改比例、政体变更会即时重测。只使用原生收入修正与实时收入读数，不额外执行整套原生预算来寻找比例，不遍历地方。普通稳定情况约4次人物修正刷新；首次修改比例需要更多次。对饱和或异常修正采用有次数上限的求解，验证失败保留原分流并提示下月重试。没有做大型长局性能基准。

更新时先备份存档，再替换模组目录并重启游戏。沿用政策版本 **9**，保留随头衔保存的预算设置。收支显示可再观察一个结算月。

0.6.7 已按 1.21.0.3 原版脚本和引擎导出接口做静态核对，并用隔离开局确认威尼斯启用统筹与俸禄、发展和军事预算。长局月度结算、旧存档和多人联机未实测。

## 0.6.5 预算与待遇控制

发展、军事改为直接互调的整数份额；俸禄新增手动待遇微调与恢复自动。所有相关箭头统一左键1个百分点、右键5个百分点。面板读当前实际拨款、基础值与明细，不再把尚未执行的原生法案权重预览混入新控件。原生0%法案的预算通道也能经直接份额重新启用；复用原有原生重算流程，不增加每次执行的预算重算次数。

保留0.6.3的连续工资曲线、10%支付上限、原生官职品级差别，以及当前实付名单与二级tooltip。游戏内结果见随包验证记录。本次不以旧存档升级为验收范围。
